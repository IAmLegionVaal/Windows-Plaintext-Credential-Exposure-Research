# Safe lab validation

## Goal

Prove that the audit and hardening controls behave correctly without collecting or exposing a real password.

## Lab topology

Recommended:

```text
LAB-DC01      Windows Server domain controller
LAB-SRV01     Member server / RDP target
LAB-CLNT01    Windows client / admin source
LAB-SIEM01    Optional log collector
```

Requirements:

- isolated virtual switch
- no production trust
- synthetic domain and accounts
- snapshots
- no reused passwords
- EDR or Sysmon telemetry
- test data marked clearly

## Validation phases

### Phase 1 — baseline

Run:

```powershell
.\scripts\Test-WindowsCredentialExposure.ps1 `
    -OutputDirectory .\report-baseline `
    -IncludeCompliantServices
```

Confirm:

- no credential value is present in output
- registry values are reported accurately
- Credential Guard state matches `msinfo32`/Device Guard WMI
- service identities are classified correctly
- JSON parses successfully
- CSV opens correctly

### Phase 2 — simulated parser testing

Use:

```text
examples/simulated-findings.json
```

The file contains synthetic findings such as WDigest enabled, wildcard delegation, and a privileged ordinary service account. Feed it into SIEM ingestion, dashboards, or automation without changing a real endpoint.

### Phase 3 — secure hardening preview

```powershell
.\scripts\Set-WindowsCredentialHardening.ps1 `
    -DisableWDigest `
    -PreventDomainCredentialStorage `
    -EnableRemoteCredentialGuardHostSupport `
    -DisableDefaultCredentialDelegation `
    -LsassASRMode Audit `
    -WhatIf
```

Review the operations and backup path.

### Phase 4 — apply secure controls

Apply one control at a time. Reboot when required. Re-run the audit after each step.

### Phase 5 — RDP mode behavior

Use synthetic accounts.

Remote Credential Guard:

```powershell
mstsc.exe /remoteGuard
```

Restricted Admin:

```powershell
mstsc.exe /restrictedAdmin
```

Validate:

- Remote Credential Guard uses Kerberos
- IP address connection fails rather than silently reducing protection
- SSO works in Remote Credential Guard
- outbound user SSO does not work in Restricted Admin
- RDP target never receives a reusable user credential in protected modes
- helpdesk process documentation matches behavior

### Phase 6 — gMSA migration

Create a synthetic gMSA and assign it to a noncritical test service. Validate:

- authorized host can retrieve the managed password
- unauthorized host cannot
- service starts after reboot
- interactive logon is denied
- group membership is least privileged
- Kerberos uses expected SPN and AES

## Prohibited validation activities

Do not:

- dump LSASS
- scrape MSTSC memory
- decrypt Credential Manager entries
- export DPAPI master keys
- publish real service passwords
- enable insecure WDigest on production
- place a test service account in Domain Admins
- use production credentials in screenshots
- upload memory dumps to public malware-analysis services

## Evidence package

Collect:

- audit JSON/CSV
- GPO/Intune configuration export
- screenshots of policy state
- relevant event IDs
- EDR alerts generated by approved simulations
- compatibility test results
- rollback result
- change record

Redact:

- usernames where unnecessary
- tenant/domain names
- device serials
- IP addresses
- tokens
- certificates
- passwords/hashes
